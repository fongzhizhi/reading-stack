# 书单模板使用说明

> 本文件是给「人 / AI」看的生成说明书，**不随书单复制、不进入产出物**。
> 产出物 = 同一目录下的 `README.md`（纯净模板，本身不含任何注释，直接填空即可，保证产物中不会残留说明性注释）。

---

## 怎么用

1. 复制模板目录（`README.md` + `books/` + `notes/`，**不要**复制本说明文件）到 `大分类/书单名/`。
2. 填空：frontmatter → 阶段名 → 导读 → 书目清单 → 自由区章节。模板里的「口气示范」是写作引导，生成时替换成书单自身的内容，不要原样保留。
3. 收尾验证：
   - `npm run check` —— 校验「书目清单 ↔ books/ ↔ notes/」三点对齐
   - `npm run index` —— 把新书单刷进根 README 一览表

**发给 AI 的两种姿势：**

| 姿势 | 发什么 | 适用 |
| :--- | :--- | :--- |
| 日常 | 只发 `README.md` | 占位引导已够用，产出的就是有示范气质的书单 |
| 高质量 | `README.md` + 本说明，并注明「其中的「写作风格指南」是写作规则，不得作为内容输出」 | 想一步到位达到观澜/定锚的水平 |

## 契约区：产出物中必须保持

以下部分脚本依赖，**格式不能动，内容必须如实填写**：

### 1. frontmatter（文件最顶部）

```yaml
---
name: 书单名          # 书单名，与目录名一致（中文）
created: 2026-08-14  # 创建日期（建书单时填当天）
updated: 2026-08-14  # 可选：最近活动日期。开始读 / 读完 / 调整书单时顺手改成当天，一览表排序优先用它；缺省退回 created，再缺省按目录名
category: programming # 大分类，必须与其所在目录名一致（programming / history / economics / psychology / yi / zhuzi / literature / others）
description: 一句话   # 简介，会展示在根 README 一览表
---
```

### 2. 书目清单表格

- 每行一本书，「书籍」列必须用《书名》包裹（如 `《重构》`）。
- **书名 = 主键**：与 `books/<书名>.md`、`notes/<书名>/` 目录名完全一致。
- **书名不带版本号**（如写 `《重构》` 而非 `《重构（第2版）》`），版本要求放「版本要求」列，否则脚本会判成两本书。
- 已收集到电子书的书，在 `books/` 建同名详情页，并把链接填进表格「详情页」列。

## 自由区：正文怎么写都行

- 「怎么读」「验收标准」是建议保留的最小骨架，保证书单有实用价值。
- 其他章节从模板末尾的「可选章节」里挑，或按书单气质自创，写多写少、写严肃写活泼都行。
- 参考样例：定锚（完整的战术手册风格：使命宣言 / 每日守则 / 紧急频率）、观澜（心法戒律 + 验收三问）。

## 写作风格指南：如何写出「观澜」级别的书单

> ⚡ 本章是**写作指令**：约束你（AI）产出内容的水平，**不得作为内容本身输出到产物中**。
> 写完比照最下方「自检清单」，达不到就补，直到过关。

### 0. 先想清楚：你在给谁写

书单 README 是**写给使用者自己**（大概率半年后回头看）和误入的同路人看的。
所以：写「**在你的场景里具体怎么读**」，而不是「**一般怎么读书**」。

### 1. 平庸 vs「观澜级」对照表（核心差距）

| 章节 | 平庸写法（填表） | 观澜/定锚/筑基写法（定制指南） |
| :--- | :--- | :--- |
| **导读** | "本阶段读三本书，打好基础。" | 点题金句 + 一句话使命：「此阶段只做一件事：死磕基本功。四书贯通之日，便是根基初成之时。」 |
| **书目清单** | 作者 + 书名表格 | 每本书一个**角色定位**：定盘星 / 破壁人 / 登高梯；立骨 / 磨锋 / 活眼 / 正心 |
| **怎么读** | "建议每天读一点，注意方法。" | 具体到**时间 / 顺序 / 动作**：「每天 40 分钟，多一分钟都不要」「第 1 周看纪录片热身，第 2-4 周精读」「每章必画五行生克流程图」「遮住断语，自行先断」 |
| **验收标准** | "能复述主要内容。" | **做出来才算**，可自测、有产物：「用缓存理论解释 Vue 为什么必须绑 key」「随手拿一个陌生八字，能独立断格局、用神喜忌」 |
| **心法 / 戒律** | "要坚持、要用心。" | 具体到心态机制与禁忌：「先见林，再见木」「戒以今度古」「卡壳时立起身、看窗外绿植，回头再读必有灵光」 |
| **收尾** | "祝阅读愉快。" | 金句 + 召唤：「现在，翻开第一页。我在这里，随时等你来问。」 |

### 2. 写作要诀（有疑问时按此优先级）

1. **具体 > 抽象**：能写"第 1-2 周"就不写"前期"；能写"每天 20 分钟"就不写"定期"
2. **命令式 > 建议式**：给指令口吻（"只允许读第 1/3/6 章，其余跳过"），不给建议口吻
3. **有产物 > 有感想**：验收写"做出来才算"（重构 80 行函数且测试全绿），不写"读懂了"
4. **个性化 > 通用**：捞使用者的场景——他的项目、他的作息、甚至他的性格（定锚写"你命局丙火双午，性易躁急"）
5. **书中之书 > 书单清单**：每本书在阶段里要有**分工和顺序**（谁的骨架、谁的案例、谁当字典），否则只是一份目录

### 3. 生成后自检清单（逐项过，不过就补）

- [ ] 导读里能圈出一句**点题金句**吗？
- [ ] 「怎么读」里有具体的时间、顺序、或动作吗？（还是泛泛而谈？）
- [ ] 验收标准是"**做出来**"而不是"读完"吗？
- [ ] 每本书有**角色/分工**吗？
- [ ] 收尾有**金句或召唤**吗？（有则成，无则补一句）
- [ ] 整体像「导师在布置任务」，不像「目录清单」？

## 常见坑

| 坑 | 后果 |
| :--- | :--- |
| 书名带了版本号 | check 报「孤儿」，脚本认为是两本书 |
| 书单名改了但 frontmatter `name` 没改 | 览表显示错名 |
| `category` 与目录名不一致 | 一览表分类列错 |
| books/ 建了详情页但没登记进书目表 | check 报「孤儿」 |
