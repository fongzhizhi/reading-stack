# 📐 维护说明

> 本仓库的工程约定都集中在这里。日常维护就四件事：**开书单、加书、写笔记、跑脚本**。

---

## 🌳 目录结构

```
/reading-stack/
├── programming/          # 大分类（英文，对 git 与链接友好）
│   └── 定锚/              # 书单（中文，人类可读）
│       ├── README.md     # 书单导航（含 frontmatter）
│       ├── books/        # 每本书一个 <书名>.md：介绍 + 如何获取
│       └── notes/        # 每本书一个目录，目录内 README.md 记元数据
├── .template/            # 模板（booklist/ 开新书单时复制）
├── scripts/              # index.mjs（聚合）· check.mjs（校验）
└── docs/                 # 本维护说明
```

**三级结构**：`大分类 / 书单 / {README.md, books/, notes/}`。其余大分类：`history / economics / psychology / yi / zhuzi / literature / others`。

---

## ➕ 新增一个书单

1. 复制 [`.template/booklist/`](../.template/booklist/README.md) 的 `README.md` + `books/` + `notes/` 到 `大分类/书单名/`（**不要**复制其中的 [usage.md](../.template/booklist/usage.md)，那是给生成者看的）。
2. 按 [usage](../.template/booklist/usage.md) 填 frontmatter（`name / category / description`）与其他内容。
3. 在 `README.md` 里写「书目清单 / 怎么读 / 验收标准」，参考 [定锚](../programming/定锚/README.md) 的写法。
4. 收集到书 → 在 `books/` 建 `<书名>.md` 详情页。
5. 开始读 → 在 `notes/` 建 `<书名>/README.md` 笔记目录。

---

## 📖 只想读一本书？

不必另起一套结构。书单本来就是「一套书」的单位，单本也兼容：把它当**单本书单**，清单表只写一行，`books/`、`notes/`、三个脚本、根 README 一览表全部照常工作，什么都不用改。

---

## 🔗 命名：书名 = 主键，三点对齐

一本书的书名同时出现在三处，**必须完全一致**，脚本靠它做校验与聚合：

| 位置 | 文件 | 内容 |
| :--- | :--- | :--- |
| 书单 README | 书目清单表「书籍」列（`《书名》`） | 一行一本书 |
| books/ | `<书名>.md` | 书籍介绍 + 如何获取 |
| notes/ | `<书名>/README.md` | 阅读笔记 + 元数据 |

⚠️ 书名不带版本号（版本要求写清单表的「版本」列），否则 `重构` 与 `重构（第2版）` 会被判为两本书。

---

## ☁️ 电子书本体不入库

`books/` 只放 `<书名>.md` 详情页。**epub / pdf 等二进制文件放网盘**（`.gitignore` 已挡），详情页里写获取方式（网盘链接 / z-lib），并保留「书名 + 作者 + 版本」作为链接失效后的溯源依据。

---

## 🧾 frontmatter 约定

- **书单 README**：`name / created / updated / category / description`（`created` 创建日；`updated` 可选，最近活动日（开始读/读完时顺手改成当天），一览表排序优先用它，缺省退回 `created`，再缺省按目录名。**不再手填 `status`**：一览表的总状态由清单书籍的阅读状态汇总——全部读完→已读，有任一本在读→在读，否则未读）
- **books/书名.md**：`book / author / version / created / updated`（`created` 入栈日；`updated` 最近活动日（读完、更新获取方式时顺手改当天），读书记录排序优先用它，缺省退回 `created`，再缺省用文件更新时间）
- **notes/书名/README.md**（笔记导航页）：`book / status / created / updated / finished / rating / tags`（`status`: **reading** 在读 | **readed** 读完，只此两个值，其他值或为空一律视为未读；`created` 开笔记日；`updated` 最近更新日，随手改；`finished` / `rating` / `tags` 读完时填）
- **notes/书名/YYYY-MM-DD-主题.md**（单篇笔记）：`title / book / created / updated`（`title` 文件名；`book` 书名；`created`/`updated` 写/更新日，供排序）

笔记正文自由发挥；多篇笔记用 `YYYY-MM-DD-主题.md` 命名，`note` 脚本会在导航页「📇 笔记索引」自动登记（手动补登也行）。

## 🛠️ 脚本

```bash
npm run index    # 聚合各书单 frontmatter，重生成根 README 的「书单一览 + 读书记录」两个占位区（可重复跑）
npm run check    # 校验「书单书目 ↔ books/ ↔ notes/」三点对齐 + frontmatter 契约 + 详情页链接有效性
npm run scaffold [src]  # 补齐书单结构：books/ 目录 + <书名>.md 详情页 + 清单表「详情页」列链接
npm run note <笔记目录> [笔记名]  # 为一本书新建一篇笔记，如 note programming/定锚/notes/程序员修炼之道（首次建笔记自动补 README.md 导航页）
npm run note:sync <笔记目录>  # 同步导航页索引（删死链登记、补漏登笔记），删过笔记后跑一次
```

- **`scaffold` 的 src 可省略（= 当前目录），或指向任意层级**：项目根 → 处理所有书单；学科目录 → 处理其下所有书单；书单目录 → 只处理它。每个书单执行前校验（README 存在 + frontmatter + 书目清单表），不合格输出原因并跳过。幂等：已存在的文件、已有内容的链接一律跳过不覆盖；书单更新了（表格加了新书）重跑即可补上。详情页骨架来自 [`.template/book.md`](../.template/book.md)（占位符 `{{书名}}/{{作者}}/{{版本}}` 由脚本替换，`{{创建日期}}/{{更新日期}}` 自动填当天），改详情页格式改那个文件即可，只对新生成的生效。
- **`check` 的规则**：清单表必须含「书籍」列（其他表格里的《》不算书）；`books/`、`notes/` 有而清单没登记的 → 错误（孤儿）；清单有但缺详情页 → 提醒（未收集）；书单总状态推导为「在读」时缺笔记 → 提醒（未读书单不报，那是预期）；有笔记目录但导航页 `status` 未识别（非 `reading`/`readed`）→ 提醒补状态；导航页索引登记了不存在的笔记 → 错误（死链），笔记文件存在但没登记 → 提醒；详情页链接 decode 后必须指向真实文件，写错（含 URL 编码错误）→ 错误。加 `-- --strict` 把提醒也升级为错误（CI 用）。
- **`index` 的规则**：书单一览按分类分组、每类一张表（无书单的分类不建表），分类顺序与标题见 [`lib.mjs` 的 `CATEGORY_MAP`](../scripts/lib.mjs)，分类内按 `updated`（缺省 `created`，再缺省目录名）降序；**「状态」列不读书单 frontmatter，由 `booklistStatus` 汇总清单书籍的阅读状态**（全部读完→已读，有在读→在读，否则未读）；读书记录分三张表（已读 / 在读 / 未读），按书籍详情页 `updated`（缺省 `created`，再缺省文件更新时间）降序，未收集详情页的书不生成链接、排在最后；「笔记」列指向 `notes/<书名>/README.md`，无笔记显示「无」。同时检查 frontmatter（`name`/`category` 合法性），发现契约问题只提示不落盘。
- **`note` 的规则**：笔记目录必须是 `<书单>/notes/<书名>` 形式（如 `programming/定锚/notes/程序员修炼之道`），不存在会自动创建；脚本从路径推导书单，校验其存在、含 README.md 且 frontmatter name 与目录名一致，再校验书名必须在书目清单表里登记过；笔记名可选，默认「YYYY-MM-DD-HHmm」，重名一律不创建（报错提示）。笔记页来自 [`.template/note.md`](../.template/note.md)，导航页来自 [`.template/note-nav.md`](../.template/note-nav.md)（占位符 `{{书名}}/{{笔记名}}/{{创建日期}}/{{更新日期}}` 由脚本替换，日期自动填当天），改格式改模板文件即可，只对新生成的生效。首次为一本书建笔记时自动生成导航页（索引表预置首行），之后每篇笔记自动在「📇 笔记索引」表末尾追加一行，无需手工登记。
- **`note:sync`（同步索引）**：`npm run note:sync <笔记目录>` 把导航页索引表与实际文件对齐——删掉登记了但笔记文件不存在的行（死链）、补上存在但没登记的行（日期取笔记 frontmatter `updated`，缺省 `created`，再缺省当天）。手动删过笔记、或把旧笔记直接拷进目录后跑一次即可。`check` 会报告这两类不一致。⚠️ 同步有独立命令入口 `note:sync`，**不要**在 `npm run note <目录> --sync` 里传 `--sync`：npm 会吞掉以 `-` 开头的参数，脚本收不到就误走新建分支（`npm run note <目录> -- --sync` 显式分隔也不行的话用 note:sync）；node 直接跑时 `node scripts/note.mjs <目录> --sync` 也兼容。

零依赖，仅需 Node ≥ 18。
