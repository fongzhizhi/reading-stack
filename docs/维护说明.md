# 📐 维护说明

> 本仓库的工程约定都集中在这里。日常维护就四件事：**开书单、加书、写笔记、跑脚本**。

---

## 🌳 目录结构

```
/reading-stack/
├── programming/          # 大分类（英文，对 git 与链接友好）
│   └── 定锚/              # 书单（中文，人类可读）
│       ├── README.md     # 书单导航（含 frontmatter）
│       ├── books/        # 每本书一个 <书名>.md：介绍 + 如何获取
│       └── notes/        # 每本书一个目录，目录内 README.md 记元数据
├── .template/            # 书单模板，开新书单时复制
├── scripts/              # index.mjs（聚合）· check.mjs（校验）
└── docs/                 # 本维护说明
```

**三级结构**：`大分类 / 书单 / {README.md, books/, notes/}`。其余大分类：`history / economics / psychology / yi / zhuzi / literature / others`。

---

## ➕ 新增一个书单

1. 复制 [`.template/书单模板/`](../.template/书单模板/README.md) 的 `README.md` + `books/` + `notes/` 到 `大分类/书单名/`（**不要**复制其中的 [使用说明.md](../.template/书单模板/使用说明.md)，那是给生成者看的）。
2. 按 [使用说明](../.template/书单模板/使用说明.md) 填 frontmatter（`name / category / status / description`）与其他内容。
3. 在 `README.md` 里写「书目清单 / 怎么读 / 验收标准」，参考 [定锚](../programming/定锚/README.md) 的写法。
4. 收集到书 → 在 `books/` 建 `<书名>.md` 详情页。
5. 开始读 → 在 `notes/` 建 `<书名>/README.md` 笔记目录。

---

## 📖 只想读一本书？

不必另起一套结构。书单本来就是「一套书」的单位，单本也兼容：把它当**单本书单**，清单表只写一行，`books/`、`notes/`、三个脚本、根 README 一览表全部照常工作，什么都不用改。

---

## 🔗 命名：书名 = 主键，三点对齐

一本书的书名同时出现在三处，**必须完全一致**，脚本靠它做校验与聚合：

| 位置 | 文件 | 内容 |
| :--- | :--- | :--- |
| 书单 README | 书目清单表「书籍」列（`《书名》`） | 一行一本书 |
| books/ | `<书名>.md` | 书籍介绍 + 如何获取 |
| notes/ | `<书名>/README.md` | 阅读笔记 + 元数据 |

⚠️ 书名不带版本号（版本要求写清单表的「版本」列），否则 `重构` 与 `重构（第2版）` 会被判为两本书。

---

## ☁️ 电子书本体不入库

`books/` 只放 `<书名>.md` 详情页。**epub / pdf 等二进制文件放网盘**（`.gitignore` 已挡），详情页里写获取方式（网盘链接 / z-lib），并保留「书名 + 作者 + ISBN/版本」作为链接失效后的溯源依据。

---

## 🧾 frontmatter 约定

- **书单 README**：`name / created / updated / category / status / description`（`status`: 未开始 | 在读 | 读毕；`created` 创建日；`updated` 可选，最近活动日（开始读/读完时顺手改成当天），一览表排序优先用它，缺省退回 `created`，再缺省按目录名）
- **books/书名.md**：`book / author / version / formats / sources`
- **notes/书名/README.md**：`book / status / finished / rating / tags`（`status`: 在读 | 读完 | 弃读）

笔记正文自由发挥；多篇笔记用 `YYYY-MM-DD-主题.md` 命名，在目录 README 里登记索引。

## 🛠️ 脚本

```bash
npm run index    # 聚合各书单 frontmatter，重生成根 README 的「书单一览 + 读书记录」两个占位区（可重复跑）
npm run check    # 校验「书单书目 ↔ books/ ↔ notes/」三点对齐 + frontmatter 契约 + 详情页链接有效性
npm run scaffold [src]  # 补齐书单结构：books/ 目录 + <书名>.md 详情页 + 清单表「详情页」列链接
```

- **`scaffold` 的 src 可省略（= 当前目录），或指向任意层级**：项目根 → 处理所有书单；学科目录 → 处理其下所有书单；书单目录 → 只处理它。每个书单执行前校验（README 存在 + frontmatter + 书目清单表），不合格输出原因并跳过。幂等：已存在的文件、已有内容的链接一律跳过不覆盖；书单更新了（表格加了新书）重跑即可补上。详情页骨架来自 [`.template/书籍模板.md`](../.template/书籍模板.md)（占位符 `{{书名}}/{{作者}}/{{版本}}` 由脚本替换），改详情页格式改那个文件即可，只对新生成的生效。
- **`check` 的规则**：清单表必须含「书籍」列（其他表格里的《》不算书）；`books/`、`notes/` 有而清单没登记的 → 错误（孤儿）；清单有但缺详情页 → 提醒（未收集）；「在读」书单缺笔记 → 提醒（未开始书单不报，那是预期）；详情页链接 decode 后必须指向真实文件，写错（含 URL 编码错误）→ 错误。加 `-- --strict` 把提醒也升级为错误（CI 用）。
- **`index` 的规则**：书单一览按分类分组、每类一张表（无书单的分类不建表），分类内按 `updated`（缺省 `created`，再缺省目录名）降序；读书记录分三张表（已读 / 在读 / 未读），按 `books/<书名>.md` 的更新时间排序，未收集详情页的书不生成链接、排在最后。同时检查 frontmatter（`name`/`category`/`status` 合法性），发现契约问题只提示不落盘。

零依赖，仅需 Node ≥ 18。
